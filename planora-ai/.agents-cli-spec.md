# Agent Spec

## Overview
Planora AI is a local-first event-planning workspace. A tool-using assistant turns natural-language event requirements into a persistent plan, budget, timeline, ideas, and guest/vendor records. Changes should update only affected plan data. The MVP covers weddings, birthdays, anniversaries, college and corporate events, community gatherings, cultural and religious celebrations, and custom events.

## Example Use Cases
- Create an event from a sentence describing type, location, date, duration, budget, guest count, and preferences.
- Generate a planning strategy, category budget, milestones, and event-day run sheet.
- Change the guest count, budget, date, or event details and recalculate affected items.
- Track tasks, actual expenses, guests, and user-entered vendor records.
- Ask for ideas, invitation copy, or alternatives when a schedule or budget changes.

## Tools Required
- Local ADK tools for event creation and updates, plan and idea generation, budget calculation and optimization, timeline creation and rescheduling, guest management, invitation drafting, task status, event-day schedules, alternatives, and reports.
- SQLite persistence for events, tasks, expenses, guests, vendors, and conversation history.
- Gemini API via server-side environment configuration when credentials are available. The local prototype must retain useful deterministic planning and tool execution without credentials.
- Vendor search must use only user-entered records in this prototype. Do not invent vendors, availability, ratings, contact details, or quotes.

## Constraints & Safety Rules
- Local prototype only; no cloud deployment, payments, bookings, invitations, emails, or third-party contact.
- Do not send invitations, book vendors, make payments, or contact anyone. Draft invitation content only.
- Make estimates visibly distinct from verified quotations and keep all costs within the stated budget unless explaining a trade-off.
- Respect dietary, cultural, accessibility, and personal requirements.
- Keep API keys on the server and never require credentials for core local demo flows.
- Label any seeded example records as demo data; use an empty user-entered vendor directory by default.

## Success Criteria
- A responsive dashboard can create and persist an event from natural-language input.
- A real assistant tool path creates or updates event records, budget categories, planning tasks, and event-day schedule.
- Budget totals, actual spend, remaining amount, and completion state are derived from stored records.
- Vendor and guest modules persist user-entered data; vendor results never imply external verification.
- The local app can run without a cloud account; Gemini-backed conversation is enabled by a server-side key when configured.

## Reference Samples
- Current `contrib/python/retail-product-search`: reuse the separation of retrieval tools from the agent and the instruction to report only sourced catalog details.
- Current `contrib/python/staged-ui-widgets`: reuse the principle that tools stage structured state while deterministic application code owns UI rendering and validates displayed data.
- The older `genmedia-for-commerce` sample named in the installed skill catalog is no longer at its documented path in the current official repository.

## Architecture & Non-Functional Requirements
- React + TypeScript + Vite + Tailwind + Recharts frontend; FastAPI + ADK backend; local SQLite persistence.
- Keep API keys server-side. No cloud deployment or external integrations are configured by default.
- Provide concise run instructions and a graceful no-credentials local assistant mode.
